# Musomi Manager V1.0.0-rc2 — Release Candidate Notes

**Review date:** 10 November 2026
**Release state:** Release candidate 2; production/pilot sign-off pending.

## Included

- Administrator, teacher, and student sign-in and role-specific access.
- School academic structure, students, teacher accounts and assignments.
- Student login provisioning and individual administrator-set student passwords.
- Topic-tagged assessments, mark entry, validation, publication, and score history.
- Student web portal for published marks, results, profile, password changes, and report downloads.
- Individual PDF report cards and class performance summaries.
- Desktop account/profile settings and global search.
- Production profile with required environment-supplied database credentials, JWT secret, and persistent report-storage directory.
- Development-only V099 sample seed separated from production migrations; a Testcontainers test proves fresh production databases receive no demo records and existing development migration history remains valid.
- A repeatable development-only migration corrects the seeded admin/teacher password hash only when it still matches the original seed hash; manually changed credentials are preserved.
- Normal logging no longer prints SQL statements or DEBUG application details.
- Legacy seeded desktop assessment store is no longer initialized by the live application.
- Re-enabled published-assessment integration test now fills the real test roster through the API before publishing.

## Verification performed

- Backend: JDK 21, Maven clean verify — 180 tests, 0 failures, 0 errors, 0 skipped.
- Desktop: JDK 21, Maven clean verify — 61 tests, 0 failures, 0 errors, 0 skipped.
- PostgreSQL 16 integration databases migrated through Flyway V101.

- Original development database and persistent Docker volume were retained.

## Known limitations / final gates

- The desktop JAR is not yet a self-contained Windows installer. A tested pilot distribution package must be produced before installing the desktop client on school computers.
- No production/pilot server or domain was supplied for deployment and HTTPS verification.
- Full role-based acceptance workflow must be demonstrated on the actual running app with approved admin, teacher, and student accounts.
- Production backup scheduling and restore drill must be configured on the pilot server.
- Class-summary PDF export and desktop stream filtering in Reports remain enhancements to decide against pilot needs.
- Real teachers/admins/students have not yet signed off the user guides or acceptance workflow.

This candidate is suitable for final controlled pilot preparation after the remaining gates are completed. Do not describe it as deployed or production-proven until those checks have passed.
