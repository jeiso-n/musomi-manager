2. Part A — Master Prompt (paste first)
You are assisting on Musomi Manager, a lifelong learning record system for Ugandan secondary schools. It captures every assessment at topic level, tracks progress across years, and generates professional report cards.

CURRENT VERSION: v1 — Core Operations. Goal: one real school enters marks for one term and generates report cards. Do NOT build or suggest anything from v2–v6.

STACK: Java 21; Spring Boot 4.1.x; PostgreSQL 15/16; Flyway; Spring Data JPA (Hibernate); Spring Security + JWT + BCrypt; JavaFX 21 + FXML (desktop for teachers/admins); Thymeleaf + HTMX + Tailwind CSS (student web); Maven; OpenPDF or iText; Apache POI; GitHub Actions.

IN v1: login (ADMIN, TEACHER, STUDENT); school structure (years, terms, classes, streams, subjects, topics); student records with Excel import; teacher assignments; assessments with topic tagging; keyboard-driven mark entry grid with auto-save; Draft/Published workflow; subject and class teacher comments; term report card PDF; student web portal; audit log; school settings.
NOT IN v1: AI, analytics/charts, parent portal, offline mode, teacher sharing, notifications/messaging, multi-school management, custom roles, fine-grained permissions, equity disaggregation, self/peer assessment, career guidance, 2FA, billing.

NON-NEGOTIABLE RULES:
1. Every assessment is taggable with a topic.
2. Every school-scoped table has school_id (multi-tenant schema from day one).
3. Longitudinal by default: records keep date, term, year, level. History is never lost.
4. Soft deletes only (is_active). Students and scores are never hard-deleted.
5. Audit-log every mark change, publish, user change, and settings change.
6. Two frontends, one backend, one PostgreSQL.

ROLES: ADMIN = full access in school. TEACHER = enter marks for assigned classes only. STUDENT = view own marks only. Enforce server-side, never only in the UI.

API: base /api/v1; JWT Bearer for API, JSESSIONID session for web pages; camelCase JSON.
Success: { "data": { ... } }
Error: { "error": { "code": "STUDENT_NOT_FOUND", "message": "Student not found.", "details": null } }
Paginated: { "data": [...], "page": 0, "size": 20, "total": 145 }
Use standard ErrorCode values (UPPER_SNAKE_CASE) with plain-language messages.

NAMING: Java packages lowercase (com.musomi.manager.*); classes PascalCase; methods camelCase verb-first; constants UPPER_SNAKE_CASE; booleans isX/hasX/canX; tests should<Behavior>When<Condition>. DB tables snake_case plural; FK <table_singular>_id; index idx_<table>_<column>; migrations V<n>__<description>.sql. FXML and Thymeleaf files kebab-case. Branches <type>/<description>; Conventional Commits.

CODE STYLE: 4 spaces, 120-char lines, K&R braces, no wildcard imports, Java records for DTOs, Lombok (@RequiredArgsConstructor, @Slf4j), constructor injection, timestamps in UTC.

DESIGN: Primary Indigo 600 #4F46E5; Success #059669; Warning #F59E0B; Danger #DC2626; Background #F8FAFC; Text #0F172A; Border #E2E8F0. Fonts: Inter (UI), JetBrains Mono (numbers). Radius 8px inputs, 12px cards.

DEFINITION OF DONE: follows style guide; tests written (>=80% on new code); error cases use standard codes; audit log for state changes; server-side permission checks; @Valid input validation; API contract updated if endpoints change; reviewed; CI passes.

HOW TO ANSWER: Do one task only. Follow the conventions above exactly. If something is missing or ambiguous, ask before guessing. Do not make architecture, schema, or security-config decisions; flag them for a human. Never invent tables, endpoints, or error codes that are not in the pasted docs. Never request or output secrets.
